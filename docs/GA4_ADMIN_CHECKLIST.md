# GA4 管理画面チェックリスト（オーナー専用）

最終更新: 2026-08-26（計測レビューR2対応で出荷条件を格上げ。経緯: 外部レビューで
「履歴イベントPVがON だとコード側の修正と無関係にSPA遷移PVが二重計上され続ける」と
指摘され、確認するまで8/26以降のPVも完全には信用できないため）

`docs/ANALYTICS_SETUP.md` の初回セットアップとは別に、GA4 の管理画面（<https://analytics.google.com/>
→ 左下「管理」⚙）で確認しておくと計測の正確さが上がる項目です。**項目1は出荷条件（1回だけの
受入確認）、項目2・3は任意**です。

## 1. 拡張計測の「ブラウザの履歴イベントに基づくページビュー」を OFF にする（出荷条件・1回だけの受入確認）

- **なぜ確認するか**: このサイトはページビューを**コード側から手動で送信**しています
  （SPA のページ遷移をアプリ側で検知して送る方式）。GA4 の拡張計測にある
  「ブラウザの履歴イベントに基づくページビュー」が ON のままだと、GA4 自身も
  ブラウザの `history.pushState` を検知して**同じページ遷移を二重にページビュー
  計上する**可能性があります。これは `send_page_view:false` を指定していても止まりません
  （公式仕様として独立して発火する）。手動送信方式のこのサイトでは **OFF が正しい設定**で、
  ON のままだと**コード側のPV修正と無関係に、query-only の履歴変更のたびにGA側から
  再びPVが飛び続けます**。**これを確認するまで、2026-08-26以降のPVも完全には信用できません**。
- **確認手順**:
  1. 「管理」→「プロパティ」列 →「データの収集と修正」→「データストリーム」。
  2. 対象のウェブストリーム（めぐりびのサイト）をクリック。
  3. 「拡張計測機能」の歯車アイコンをクリック。
  4. 「ブラウザの履歴イベントに基づくページビュー」のトグルを確認。
     - **OFF になっていれば何もしなくてOK**（正しい状態）。
     - ON になっていた場合は OFF に切り替える（二重計上を止めるため）。

- **（任意・より確実にしたい場合）DebugView での実挙動確認**:
  拡張計測OFFを確認したあと、GA4 の「管理 → DebugView」を開き、スマホやPCのブラウザで
  `https://www.meguribi.jp/?dev=0` を開いてから次の5操作をして、**page_view がそれぞれ
  1回ずつだけ**流れることを見ると確実です（2026-08-26 R2レビュー提案）:
  1. 初回表示 → 1回
  2. 店舗一覧 → 店舗ページへの移動 → 1回
  3. レポート検索ボックスに数文字入力 → **0回**（増えたら異常）
  4. ブラウザの戻る/進む → 各1回
  5. ページ再読み込み → 1回
  ※ 確認が終わったら `?dev=1` を開き直して自分の閲覧を計測から除外し直すこと。

## 2. カスタムディメンションの登録（任意）

- **なぜ確認するか**: コード側では `store_slug` / `brand` / `mode` /
  `report_type` / `venue_kind` / `from_slug` / `destination_domain` といったパラメータを
  イベントに付けて送信していますが、GA4 の
  レポート画面で**ディメンションとして表示・絞り込みするには、GA4 側で
  カスタムディメンションとして登録する必要**があります。
- **重要な注意点（誤解しやすい点）**:
  - **未登録でもイベント数そのものは記録され、標準レポートには出ます**。無くても
    データが失われるわけではありません。
  - ただし**登録した「その時点より後」のデータしか、そのディメンションで
    集計・絞り込みできません**（さかのぼって過去分に反映されることはない）。
    なので、使いたいと分かった時点で早めに登録しておくのが得です。
- **確認・登録手順**:
  1. 「管理」→「プロパティ」列 →「データの表示」→「カスタム定義」。
  2. 「カスタムディメンションを作成」をクリック。
  3. 次の5つを、コード側で送っているイベントパラメータ名と**完全一致**する
     「イベントパラメータ」として登録する（ディメンション名は分かりやすい日本語でOK、
     「イベントパラメータ」欄だけは英字のパラメータ名と一致させること）:
     - `store_slug`
     - `brand`
     - `mode`
     - `report_type`
     - `venue_kind`

     ※ `surface` は 2026-08-26 のR2レビューで「どのイベントも送っていない」ことが
     確認されたため一覧から外しました（登録しても空のままになる）。将来
     送信を始めたらここに戻すこと。
  4. 登録後、GA4 の反映には多少時間がかかる（すぐには一覧に出ないことがある）。

## 3. データ保持期間（14ヶ月）の確認（任意）

- **なぜ確認するか**: GA4 の初期設定は「2ヶ月」です。標準の集計レポートやAPI集計
  （`scripts/analytics_report.py` や週次ダイジェストが使う経路）自体は保持期間の影響を
  受けません（公式仕様。保持期間が短くても集計値は消えません）が、**Explorations等で
  イベント単位の詳細分析をする可能性への備え**として、
  `docs/ANALYTICS_SETUP.md` の初回セットアップ手順（§2-3）で 14ヶ月に変更済みのはずです。
  ここでは**変更が維持されているかどうかの確認だけ**を行います。
- **確認手順**:
  1. 「管理」→「プロパティ」列 →「データの設定」→「データ保持」。
  2. 「ユーザーデータとイベントデータの保持」の中の「イベントデータの保持」が
     「**14 か月**」になっていることを確認する。
  3. もし「2 か月」に戻っていたら（プロパティ再作成時などに初期値へ戻ることがある）、
     14ヶ月に変更して保存する。
